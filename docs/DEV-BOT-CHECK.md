# DEV: заказ и постоянное меню — 06.11.2026

## Изменение

После /start и /menu бот присылает постоянную ReplyKeyboardMarkup с кнопками «Меню», «Заказы», «Каталог», «Помощь», «Отмена ввода». is_persistent=true, one_time_keyboard=false, resize_keyboard=true. Inline-кнопки конкретных действий сохранены отдельно.

Навигация обрабатывается до ввода редактора, поэтому название раздела не становится названием товара. На каждый запрос снова проверяются реальный отправитель, личный чат и действующая запись сотрудника. Права задаются прежним permissions.ts.

Добавлена команда /orders. processing отображается одинаково: «в обработке». Дополнительное подтверждение требуется для выдачи и отмены; переход нового заказа в обработку выполняется сразу.

Нативный список команд около поля ввода настраивается python3 ops/dev/configure-menu.py; скрипт проверяет getMe и работает только с @testmw639bot. connect-telegram.py вызывает его при подключении DEV. Источник команд и подписей — src/lib/bot/navigation.json.

## Проведённая проверка

В 05:40–05:42 по Москве через Chromium на DEV-сайте оформлен учебный заказ #e83b0d20 (900 ₽, DEV QA E2E-20261106-0240).
ops/dev/verify-order-flow.ts использовал настоящий DEV REST, тот же handleUpdate и processClaimedUpdate, реальные отправки в @testmw639bot в явно разрешённый чат владельца.

Проверены:
- список заказов содержит callback нужного заказа в настоящем ответе Telegram;
- карточка содержит кнопку new → processing;
- переход сохраняет processing, отправляет подтверждение и обновлённую карточку;
- одна запись order_events; повтор update_id не повторяет мутацию и отправку;
- Telegram принял сообщение с постоянной клавиатурой; всего 6 настоящих сообщений.

**Граница проверки:** входящие Update сформированы тестом. Два answerCallbackQuery для искусственных callback ID заменены тестовым ответом, поскольку настоящего нажатия в Telegram-клиенте не было. Это не визуальный тест Telegram и не доказательство реальной доставки входящего callback через Telegram. Подключённого browser-skill браузера не обнаружено. Авторизация, чтение и изменение БД, аудит, дедупликация, формирование кнопок и доставка сообщений были настоящими.

Никаких тестовых обходов в приложение/webhook не добавлено. Подмена callback acknowledgement существует только в отдельной запускаемой вручную DEV-проверке. Она отказывается менять уже обработанный или неучебный заказ.

436 автоматических тестов приложения прошли. Добавлены проверки постоянной клавиатуры, навигации до редактора, /orders, запрета групп и отозванного доступа.
main и production не изменяются этой работой.
