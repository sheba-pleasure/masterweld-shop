# Сохранение фотографий старого каталога

Дата: 06.11.2026. Статус: инструмент проверен, реальные файлы пока не сохранены. Три запроса завершились по таймауту; 1012 URL не проверялись. Рабочий перенос фотографий заблокирован до получения исходных байтов.

## Что сохраняем

В снимке Cloud 1077 строк product_photos с 1015 уникальными URL: 700 путей .jpg и 315 .png, все на https://masterweld.ru. Одинаковый URL может относиться к нескольким строкам/товарам. Архив сохраняет все исходные связи и исходную строку URL. Для HTTP отдельно формируется корректно экранированный путь, включая кириллицу; существующие percent-escape не кодируются повторно.

Файлы сохраняются без преобразования изображения в закрытую папку снимка media/objects под именами SHA-256.jpg или SHA-256.png. Одинаковые байты нескольких URL занимают один объект, а привязки остаются отдельными. База данных и опубликованные URL не меняются. Товары, помеченные «Не продаём», не возвращаются в каталог: этот инструмент вообще не записывает товары.

## Установка инструмента

Декодер установлен отдельно от приложения и системного Python:

```sh
python3 -m venv ops/.state/media-venv
ops/.state/media-venv/bin/python -m pip install --require-hashes --only-binary=:all: -r ops/standalone/requirements-media.txt
```

Зафиксирован Pillow 12.3.0 с хешами колёс для Linux x86_64 Python 3.10/3.12; другие платформы требуют отдельной проверки зависимости. Эта версия поддерживает Python 3.10 сервера. Системные пакеты, приложение и сервисы не обновлялись. CI устанавливает тот же декодер в Python 3.12. Проверка использует verify и последующее полное load после повторного открытия, согласно [документации Pillow](https://pillow.readthedocs.io/en/stable/reference/Image.html); один заголовок изображения недостаточен.

## Проверка и продолжение

Только локальная проверка снимка, списка и ранее сохранённых объектов; сетевых запросов нет:

```sh
ops/.state/media-venv/bin/python ops/standalone/preserve-cloud-media.py ops/.state/production/cloud-export/20261106T085019Z
```

Загрузка не более десяти ещё не проверенных URL:

```sh
ops/.state/media-venv/bin/python ops/standalone/preserve-cloud-media.py ops/.state/production/cloud-export/20261106T085019Z --fetch --limit 10
```

После восстановления доступа можно включить ранее неудачные адреса:

```sh
ops/.state/media-venv/bin/python ops/standalone/preserve-cloud-media.py ops/.state/production/cloud-export/20261106T085019Z --fetch --retry-failed --limit 1015
```

Успешно сохранённые объекты повторно не скачиваются. Ранее неудачные URL повторяются только с --retry-failed; обычный запуск продолжает pending. После трёх последовательных отказов запуск прекращается, поэтому при недоступном источнике он не выполняет тысячи запросов. Лимит одной попытки — 25 секунд целиком, сетевой timeout — 8 секунд. Загрузка последовательная, между попытками пауза 0,2 секунды. Код выхода 2 означает незавершённую загрузку, 1 — отказ/ошибку самого инструмента. Успех локальной проверки без --fetch не означает, что все фотографии скачаны.

Перед загрузкой проверяется исходный снимок и неизменность перечня URL/связей. Разрешён только HTTPS-хост masterweld.ru; userinfo, query, fragment, нестандартный port, приватные DNS-адреса и переход на другой хост/HTTP отвергаются. Допустимы не более трёх переходов внутри разрешённого HTTPS-хоста. TLS-проверка не отключается.

Принимаются только JPEG/PNG с соответствующим Content-Type, размером до 20 МиБ и до 25 миллионов пикселей. Проверяются Content-Length, фактический объём, структура и полное декодирование. Анимация требует отдельного решения. Ограничения не означают, что неподходящий файл надо удалить: он остаётся отмеченным как не сохранённый, исходная строка не меняется.

## Целостность и защита от путаницы

- manifest.json содержит sourceUrl, requestUrl, все photoIds/productIds, состояние pending/failed/saved и число попыток. У успешной записи есть размер, тип, разрешение, SHA-256 и конечный URL.
- Каталог имеет права 0700, файлы — 0600 и исключены из Git. Имена объектов строятся только из проверенного хеша и типа, а не из имени исходного URL.
- Оригинал сначала полностью записывается и fsync, затем появляется под окончательным именем. Manifest обновляется атомарно. Прерванный запуск не помечает неполный файл сохранённым.
- flock запрещает одновременные операции над одним архивом. Символьные ссылки и открытые права файлов отвергаются.
- Каждый последующий запуск заново проверяет хеш и декодирование сохранённых объектов. Повреждённый оригинал не перезаписывается молча. Ошибка диска останавливает операцию и не маскируется под сетевой отказ.
- В обычный вывод попадают только агрегаты и коды ошибок. Изображения, исходные URL и служебные строки остаются в закрытом manifest.
- Каждый запуск создаёт отдельный report-*.json с хешем текущего manifest, версией кода и итогами. Старый отчёт относится к своему состоянию manifest; после продолжения его хеш закономерно изменится.

## Что дальше

1. Получить доступные оригиналы: восстановить доступ к исходным URL либо получить закрытый экспорт файлов старого хостинга. Доступы не угадывать и сетевые ограничения не обходить.
2. Продолжить загрузку, сверить 1077 связей/1015 URL и отдельно разобраться с каждым недоступным файлом. Не подставлять похожие изображения.
3. Владелец выбрал Яндекс.Диск. Прикладной архив загружен и восстановлен после скачивания, но байтов фотографий в нём нет. Дополнить копию оригиналами и проверить восстановление на другом сервере; [BACKUP-YANDEX.md](BACKUP-YANDEX.md).
4. Только после полной сверки подготовить новое место публикации и отдельную проверенную замену URL. Нынешний скрипт ничего не публикует.
5. Новый снимок перед переходом должен учитывать изменившиеся фотографии. Успешный старый архив не доказывает актуальность файлов на момент запуска.

Новая загрузка фотографий сотрудниками остаётся отдельной отложенной функцией. Этот этап сохраняет существующие изображения. Связанные материалы: [CLOUD-EXPORT.md](CLOUD-EXPORT.md), [CLOUD-TRANSFER.md](CLOUD-TRANSFER.md).
