## Порядок восстановления для администратора

1. Скачать архив и файл контрольной суммы из раздела «Текущий комплект до 0028» в новую закрытую папку вне сайта. Проверить SHA-256 по значению именно этого комплекта. Исторические папки ниже не заменяют актуальные инструменты.
2. Проверить список вложений перед распаковкой: только обычные файлы с относительными путями, без `..`, ссылок и повторных имён. Распаковать в новую папку с правами 0700; файлам назначить 0600. Не распаковывать поверх проекта или рабочей базы.
3. Прочитать `ВОССТАНОВЛЕНИЕ.txt` и сверить файлы с BACKUP-MANIFEST.json. Для проверки нужны Python 3, Docker и доступный локально образ `postgres:17.6-alpine`; Python-зависимостей для этого проверяющего инструмента нет.
4. Из корня распакованного комплекта выполнить:

```sh
python3 ops/standalone/verify-cloud-snapshot.py ops/.state/production/cloud-export/20261106T085019Z --restore --upgrade
```

5. Проверить в созданном report.json результат, совпадение строк и удаление временных ресурсов. Эта команда восстанавливает только изолированную копию. Для рабочего переноса использовать отдельную проверенную процедуру [CLOUD-TRANSFER.md](CLOUD-TRANSFER.md).

Исходный архив нельзя напрямую запускать публичным магазином: в исторической схеме есть старый прямой INSERT заказов. Миграции в закрытой проверке устраняют этот путь; это не разрешение на рабочий импорт. Технический DEFAULT new у двух старых заказов не делает их новыми обращениями. Решение владельца об их дальнейшей судьбе остаётся открытым. Сохранённые четыре сотрудника также не означают утверждённые рабочие права.
