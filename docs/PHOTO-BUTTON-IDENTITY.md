# Кнопки фотографий: привязка к изображению

## Что изменилось

Раньше кнопка содержала ID товара и номер фото в списке. После перестановки или удаления по тому же номеру могло оказаться другое изображение. Новые кнопки содержат ID самой фотографии. Обработчик проверяет актуальные права, находит её действующий товар и затем ищет только этот ID в неудалённых фотографиях. Если фото исчезло или чтение не удалось, соседнее изображение не выбирается.

Формат: pfd:PHOTO_UUID для просмотра, pfm/pfu/pfn/pfx:PHOTO_UUID для основного фото, перемещения и обратимого удаления. Каждый callback — 40 байт, ниже лимита Telegram. Старые phd/phm/phu/phn/phx:PRODUCT_UUID:INDEX не готовят новую правку и предлагают заново открыть галерею. Уже сохранённый результат старого запроса по 0025 остаётся доступен; это чтение прежнего pending, без повторного поиска по индексу.

Стрелки показываются только у обычных фотографий, которым есть куда переместиться. Основное фото закреплено; первая обычная фотография не предлагает движение выше основного. Целевая позиция рассчитывается среди обычных фото 1..n, как в SQL. Сообщение о результате отличает скрытие от восстановления из карантина. Сбой чтения галереи больше не маскируется под пустой список и не включает обход фильтра deleted_at.

Новая миграция не нужна: используется существующая схема 0025 и атомарное подтверждение 0024. SQL повторно проверяет фактический ID, принадлежность товару, состояние фотографии и снимок перед применением. Новая загрузка фотографий не включается.

## Проверки

Профильные тесты воспроизводят перестановку списка между показом кнопки и первым нажатием, замену соседа, исчезновение фото, повтор уже сохранённого запроса, старые кнопки, ошибки чтения, права сотрудника и групповой чат. Отдельно проверены границы порядка, отсутствие основного фото, длина callback и сообщения о восстановлении. Тесты используют учебные записи.

В закрытом исходном снимке Cloud 08:50 UTC: 1029 галерей, у каждой ровно одно основное фото; ранги остальных соответствуют 1..n. Источник не изменялся. На текущем DEV нет записей product_photos, поэтому настоящая перестановка в DEV не заявляется. ops/dev/verify-photo-identity.ts проверяет на настоящих HTTPS-БД и Telegram пустую галерею, отказ пяти старых кнопок и отсутствие подмены отсутствующего ID во всех новых действиях, а также отсутствие новых pending/квитанций и изменений прежних данных.
