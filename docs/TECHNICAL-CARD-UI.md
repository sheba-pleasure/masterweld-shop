# Характеристики на странице товара

Дата: 06.11.2026. Первый пользовательский этап поверх [основы P0](TECHNICAL-CATALOG-P0.md). Страница общая для браузера и магазина внутри Telegram. Этот документ описывает показ проверенных сведений. Пошаговый редактор сотрудников добавлен отдельным этапом: [TECHNICAL-EDITOR.md](TECHNICAL-EDITOR.md).

## Что видит покупатель

На странице товара появился блок «Характеристики». Он читает только публичную подтверждённую ревизию через public_product_technical. Процессы MMA, MIG/MAG, TIG, CUT и FCAW разделены; условия измерений идут непосредственно под своим значением. Ток и температура для продолжительности нагрузки, газ и охлаждение горелки, давление для расхода воздуха не берутся из соседних строк.

Ноль, «Нет», «Не указано» и «Не применяется» показаны по-разному. Числовые списки разделяются точкой с запятой, чтобы десятичная запятая не создавала двусмысленность. кВА не превращаются в кВт. Коды трёх пилотных перечислений расшифрованы словами; соответствие других моделей и пригодность для материала не выводятся автоматически.

Под параметром указан номер источника. «Источники характеристик» раскрываются кнопкой или клавишей Enter: документ, издатель, модель, раздел/страница и дата проверки. Настоящая публичная HTTPS-ссылка открывается отдельно с noopener/noreferrer. Если ссылки нет, предлагается запросить документ у магазина. Наличие хеша в БД не выдаётся за сохранённый файл.

Synthetic-источники явно обозначены как учебные; вымышленная ссылка не становится активной кнопкой паспорта. Учебная карточка DEV-001 содержит ранее сохранённые вымышленные значения. Их нельзя переносить в рабочие товары.

Прежний products.specs сохранён без изменения и доступен отдельным раскрывающимся блоком «Характеристики из прежнего описания». Он не обозначается как прошедший новую проверку по источникам.

## Обновление и ошибки

Кнопка «Обновить характеристики» повторно читает публичный API. Повторное открытие, возврат фокуса и восстановление соединения также обновляют данные. Во время запроса старый подтверждённый снимок скрыт. При отказе API видна ошибка и действие повтора; отказ не маскируется под отсутствие характеристик. Ответ null убирает прежний снимок, а переход к другому товару не переносит его значения. При offline показано ожидание соединения.

Поведение основано на установленном TanStack Query 5; [контракт useQuery](https://tanstack.com/query/v5/docs/framework/react/reference/useQuery). Это обновление по событиям, а не realtime-подписка: открытая страница не узнаёт об изменении мгновенно без нового запроса. Сервер оформления всё равно заново проверяет товар и цену.

Публичный TypeScript-контракт дополнительно отвергает несоответствие типа значения, неизвестную ссылку на источник и неоднозначные ключи источников. Service role, сотрудник и закупочные цены в этот блок не передаются.

## Оформление

Сохранены Montserrat Variable для текста, Russo One для заголовка, действующие фон/контрастный текст и фиолетовый акцент магазина. Новая палитра, шрифты, иконки или анимация не добавляются. Разделители обозначают процессы; подзаголовки обычного регистра. На узком экране значение идёт под названием, на широком — рядом. Внутри строки отступы 4–12 px, между процессами 20 px. Основное действие — открыть источник или обновить данные. Учебный статус выделен существующим светло-жёлтым фоном; текст ошибки имеет обычный контрастный цвет с красным боковым акцентом.

## Проверка и границы

Проверка фактической версии, точный SHA, снимки и результаты находятся в [VERIFICATION.md](VERIFICATION.md). Сценарий ops/dev/check-technical-card.mjs сначала читает настоящее DEV API, затем отдельно симулирует HTTP 503/null и Telegram SDK. Проверка корзины не отправляет заказ. Это не проверка новых характеристик в настоящем Telegram-клиенте или на физическом Android/iOS.

Новых миграций, записей характеристик и изменений товарных полей этот этап не делает. Этап показа не менял схему 0000–0018; последующая защита редактора обновила DEV до 0019 без изменения публичного чтения. Полный словарь, реальные паспорта/SKU, редактор и подтверждение сотрудником, варианты, технические фильтры и сравнение ещё не завершены.

Следующий этап: товар в служебном боте → собственное семейство → значения и первоисточник → предпросмотр → предложение продавца / подтверждение владельца. Подтверждённая и предложенная версии должны различаться, отмена должна проверять последующие изменения. Использовать действующий webhook, permissions.ts и аудитируемый RPC; публичный путь записи не создавать.

## Откат

Можно вернуть предыдущий совместимый DEV-образ: технические ревизии остаются в БД, старый specs остаётся без изменений. Полное восстановление БД для отмены этого интерфейса не требуется. Production и main этим этапом не обновляются.
