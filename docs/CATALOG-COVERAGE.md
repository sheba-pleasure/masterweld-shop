# Покрытие исследования словарём текущей ветки

Дата сверки: 07.11.2026. Это сравнение исходников, а не проверка наполнения товаров или живой базы. **Новые принадлежности пока не установлены в DEV:** там остаются 27 семейств и 87 определений. Фактическая версия приложения и схема — в [STATUS.md](../STATUS.md).

## Результат

Исследование содержит 48 семейств, 411 специальных привязок, 359 специальных уникальных ключей и 15 общих полей. Исходники текущей ветки содержат 131 определение и 166 привязок для 33 семейств.

| Состояние исследовательской привязки | Количество | Что это означает |
| --- | ---: | --- |
| Отдельное поле | 144 | Совпадают семейство, код и тип; это не проверка значений товара |
| Документальное обозначение | 18 | Исследование предложило enum/enum_list без полного словаря; вместо выдуманных вариантов хранится буквальный текст источника |
| Условие измерения | 13 | Ток, температура или ПН хранятся вместе с измерением |
| Значения по процессам | 1 | Мощность разделена по MMA/MIG/TIG; исходный mode_map не задаёт полной внутренней схемы |
| Частичное представление | 1 | Охлаждение MIG-горелки есть в условиях номинала, но не как отдельное свойство/фильтр |
| Нет словаря вариантов | 89 | Определения вариантов ещё не подготовлены |
| Нет привязки к семейству | 3 | Код теперь определён для принадлежностей, но не перенесён автоматически в другое семейство |
| Требуется проектирование схемы | 142 | Остальные типы без действующего определения |

Итого: 411. Это привязки «семейство — характеристика», не количество уникальных определений. Общие поля учитываются отдельно: цена, бренд, наличие, модель и происхождение документов используют существующие операции.

Из 166 привязок исходников 163 сопоставлены с исследованием, включая 18 явных изменений представления. Ещё три — дополнительные поля: диапазон диаметров вольфрама, мощность охлаждения в ваттах и полная запись электропитания. Они сохраняют исходные сведения без выдумывания промежуточных размеров или автоматического пересчёта и не увеличивают число покрытых исследовательских строк.

Буквальное обозначение не является нормализованным перечислением для фильтров. Серия горелки в карточке аппарата CUT и в TIG/CUT-расходниках остаётся отдельной непроверенной связью: совпадение кода не разрешает объявлять совместимость.

## Следующие этапы

1. **Закончить установку принадлежностей.** Подготовлены все 41 поле исследования для TIG-горелок, CUT-плазмотронов, держателей MMA, зажимов массы, кабелей и охлаждения, плюс три альтернативы переноса. До установки нужны совместная миграция 0042/0043, защита от несовместимого образа и проверка окончательной сборки. [Описание и границы](ACCESSORY-CHARACTERISTICS.md).
2. **Разобрать нормализованные варианты по первичным документам.** Восемнадцать обозначений сохраняются дословно с человеческим подтверждением. Полный словарь серий, соединений и материалов, фильтры и правила совместимости этим не подменяются. Не превращать примеры исследования в закрытый перечень.
3. **Продолжить остальные семейства и общие поля.** СИЗ — документальная маркировка без обещаний неподтверждённой защиты; газовое оборудование — газ, давление и соединение без вывода взаимозаменяемости; столы/оснастка — геометрия и условия нагрузки. Упаковка, размеры и масса не равны складскому остатку.
4. **После схемы — проверенные товары и фильтры.** Наполнение SKU, технический поиск, сравнение, группы вариантов и подбор остаются отдельной работой. Прайсы не требуются для проектирования, но окончательный ассортимент решает владелец.

Новые определения добавляются после прежних, сохраняя индексы кнопок и открытых черновиков. Перед установкой проверяются миграция, совместимость приложения, сохранность данных и сценарий человека. Откат импорта не возвращает исключённые товары. Автопубликация запрещена; Main и production не изменяются.

## Как воспроизвести

```bash
python3 ops/catalog-research-coverage.py --summary
python3 ops/catalog-research-coverage.py --summary --check docs/research/catalog-coverage-20261107.json
```

[Машинный отчёт](research/catalog-coverage-20261107.json) содержит каждую исследовательскую привязку, условия соответствия, незакрытые поля и SHA-256 входов. Скрипт только читает локальные файлы: без БД, Telegram, интернета и записи файлов. Изменение состава словарей требует явного обновления входов; документальные замены сверяются по исходному типу и семейству. --check отклоняет устаревший отчёт и включён в GitHub verify.

Это не автоматический анализ всей семантики dictionary.ts: хеш обнаруживает изменение, но композиция и исполняемые правила требуют просмотра кода. Новых резервных копий, выгрузок или расписаний эта работа не создаёт.
