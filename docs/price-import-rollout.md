# Этап D: импорт прайса и закупочных цен — развёртывание, зависимости, риски

Интернет-магазин «Мастер Сварщик». Документ описывает безопасный импорт
CSV-прайса: предпросмотр (dry-run) → подтверждение → применение одной
транзакцией → откат. Закупочные цены хранятся в защищённой таблице
`product_costs` и никогда не показываются покупателям и продавцам.

## Статус (честно)

- **Реализовано в коде:** чистый парсер CSV (`src/lib/import/price-csv.ts`),
  diff-движок с предупреждениями и redaction закупочных данных
  (`src/lib/import/price-diff.ts`), 59 синтетических тестов, кнопка
  «📥 Загрузить прайс» в боте показывает честный статус.
- **Миграция `docs/migrations/0008_price_imports.sql` НЕ применена.**
  Без неё импорт заблокирован: бот сообщает «импорт пока не активирован»,
  ложного подтверждения не бывает.
- **Загрузка файла прайса из Telegram: ЗАБЛОКИРОВАНА (fail closed).**
  Транспорт документов через gateway (getFile → /file/<path> для document)
  НЕ проверен вживую — тот же риск, что у фото (C2B). До проверки отправка
  CSV боту отвечает «загрузка файла из Telegram не подключена».
- **Живой E2E не проводился.** Это НЕ «рабочий импорт» — это подготовленный
  безопасный путь.

## Что реализовано в коде (без БД)

### Парсер `price-csv.ts`

- Только UTF-8 (BOM снимается); cp1251 и прочие кодировки — явный отказ
  `UNSUPPORTED_ENCODING`, кодировка не угадывается.
- Строгое определение разделителя (comma/semicolon/tab) с учётом quoted
  fields; неоднозначность — отказ `AMBIGUOUS_DELIMITER`.
- RFC 4180 quoted fields (экранированные `""`, переносы внутри полей);
  повреждённые кавычки — отказ `MALFORMED_QUOTES`.
- Колонки — только по явному whitelist (русские и английские имена:
  артикул/sku, цена/price, закупка/cost, наличие/stock, кол-во/qty,
  поставщик/supplier_name, источник/source_key). Неизвестные колонки —
  предупреждение, не угадываем.
- Строки без SKU — reject (`SKU_REQUIRED`); сопоставление по названию
  невозможно в принципе.
- Цены RUB: формат десятичного разделителя объявляется явно; «1,200» при
  любом формате отвергается (неоднозначно); пробелы/NBSP — разделители
  тысяч; лимит 10 000 000 ₽; без умножения на 100.
- Лимиты: 5 МБ файл, 50 000 строк, 50 колонок; строки с разным числом полей
  отклоняются (`ROW_COLUMN_MISMATCH`).
- Формульные значения (`=`, `+`, `-`, `@`) — предупреждение (не исполняются);
  экспорт CSV экранирует их апострофом (formula injection).
- SHA-256 файла (`hashText`) — для идемпотентности батча.

### Diff-движок `price-diff.ts`

- Сопоставление только по SKU. Дубли SKU **в прайсе** и дубли SKU **в
  каталоге** (в базе известно 24 пары) — manual-review, автоматическое
  применение батча блокируется целиком.
- Сводка: matched / unmatched / ambiguous / invalid / unchanged / proposed.
- Меняются только поля, **явно** переданные в `fields`: price, stock, qty,
  cost. `old_price`, статусы, категория, название, slug, source_url — вне
  движка вообще.
- Предупреждения: изменение цены > 20% (`PRICE_CHANGE_OVER_WARN`), > 30%
  (`PRICE_CHANGE_OVER_CRITICAL`), цена продажи ниже закупки
  (`SALE_BELOW_COST`), qty без подтверждения склада
  (`QTY_WITHOUT_STOCK_CONFIRM` — значение НЕ применяется).
- Закупочные цены: только при `includeCosts` (право `view_costs`); без права
  cost-строки не попадают в результат вообще, `sanitizeForRole` вырезает их
  из любого текста (продавец не видит даже предпросмотр).
- Гейты: `canAutoApply()` всегда `false` — применение только через
  `applyGate(approved=true)`; оптимистичные проверки `checkApplyConflict` /
  `checkRollbackConflict` (сравнение цен в копейках).

### Бот

- Кнопка «📥 Загрузить прайс» (право `import_prices`, только личный чат):
  пошаговая инструкция и честный статус — «импорт пока не активирован».
- Входящий document от сотрудника с `import_prices` → «загрузка файла из
  Telegram не подключена»; file_id не логируется и не сохраняется.

## Миграция 0008 (порядок после 0005–0007)

1. Таблицы `import_batches` (checksum UNIQUE — идемпотентность; статусы
   staging → approved → applied → rolled_back), `import_rows` (before/after
   снимки, построчный row_status, action только price/stock/qty/cost),
   `import_events` (журнал). RLS включён, доступ ТОЛЬКО service_role.
2. RPC (SECURITY DEFINER, REVOKE PUBLIC/anon/authenticated, GRANT только
   service_role):
   - `bot_import_create_batch` — идемпотентно по checksum, валидация всех
     значений на уровне БД, RBAC (`import_prices`; cost-строки дополнительно
     `view_costs`), лимит 10 000 строк;
   - `bot_import_approve` — approved_by + аудит;
   - `bot_import_apply` — **all-or-nothing**: блокировки FOR UPDATE в
     стабильном порядке, сверка before-снимков, UPDATE товаров +
     product_costs + row_status + аудит одной транзакцией; конфликт любой
     строки откатывает весь батч (статус остаётся approved — повторяемо);
   - `bot_import_rollback` — только applied-батч; жёсткая сверка текущего
     значения с after-снимком, иначе `BOT_IMPORT_ROLLBACK_CONFLICT`
     (100→200→300 не откатывается молча).
3. Импорт НЕ меняет категорию/название/slug/source_url/status/old_price —
   таких действий в схеме и RPC нет.

## Политика частичных сбоев

Строго **all-or-nothing**: половина применённого батча невозможна. При
конфликте — ничего не меняется, батч можно повторить после устранения
конфликта. Честный summary о причинах возвращается в исключении/логе.

## Что нужно для включения

1. Ревизия SQL 0008 (и 0005–0007, если ещё не применены) — глазами.
2. Применение миграций инструментом миграций.
3. **Живая проверка транспорта документов Telegram:** отправить боту CSV,
   вызвать `getFile` и скачать `/file/<path>` через gateway; убедиться, что
   ответ — бинарные данные. Только после этого подключать приём файла
   (тот же путь разблокирует и фото C2B — см. docs/telegram-photo-rollout.md).
4. Живой E2E на тестовом товаре с тестовым сотрудником.

## Оставшиеся риски

- **Транспорт документов не проверен** — ключевая блокировка (п. 3).
- Diff-предпросмотр для владельца пока недоступен из бота без файла; в
  режиме разработки/тестов он проверен на синтетических данных
  (`price-diff.test.ts`, `renderDiffPreview`).
- `product_costs` сейчас пуст (0 записей) — «до» для cost-строк = NULL,
  откат удалит строку, если её не было (предусмотрено в RPC).
- Параллельные правки во время импорта ловятся optimistic-сверкой в
  `bot_import_apply` (все товары батча блокируются).

## Проверка после включения

- Повторная загрузка того же файла → существующий батч, дубль не создаётся.
- Дубль SKU в прайсе/каталоге → автоприменение заблокировано.
- Изменение цены > 30% → критическое предупреждение в предпросмотре.
- Конфликт (значение изменили после предпросмотра) → apply ничего не меняет.
- Откат применённого батча возвращает before-значения; после ручной правки
  поверх — откат запрещён (конфликт).
- Продавец не видит закупочные цены ни в предпросмотре, ни в журнале.

## Откат

- Кнопка/команда отката применённого батча (preview → confirm) —
  `bot_import_rollback`, all-or-nothing со сверкой.
- Откат кода — отключение обработчика импорта; данные не пострадают.
- Откат миграции 0008: таблицы закрыты для всех кроме service_role; данные
  батчей можно оставить как историю (удаление — только по прямому решению,
  breaking-миграции запрещены).
