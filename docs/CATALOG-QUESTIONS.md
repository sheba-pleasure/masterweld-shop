# Вопросы и продолжение ввода товара

Дата: 06.11.2026. DEV: bc19479a297766ff5f0bb8d3f480c51f6bf8e92c, схема 0000–0022. Миграция не нужна.

## Сотруднику

Бот задаёт вопрос и открывает ответ на него. Пишите значение как ответ на это сообщение. Если режим ответа закрыт, выберите «Ответить» у текущего вопроса.

«✏️ Продолжить ввод» в нижнем меню или /input показывает текущий вопрос заново. При выборе раздела или на этапе подтверждения вернутся соответствующие кнопки. /cancel отменяет незавершённый ввод. После обновления прежний вопрос можно восстановить через /input.

Запоздавший ответ на старый вопрос и отдельное сообщение без привязки не меняют товар или шаг. Бот объяснит, как продолжить. Неверное значение повторяет тот же вопрос с пояснением — уже принятые название и артикул сохраняются.

При сбое доставки вопроса или сохранения его привязки используйте /input. Не начинайте /new вместо продолжения. Для восстановления результата уже подтверждённого создания используется прежняя кнопка подтверждения или «Проверить и завершить»: [инструкция](DRAFT-RECOVERY.md).

## Реализация

В приватном data строки bot_editor_states хранится _prompt_message_id. Каждый новый текстовый шаг сначала сохраняется без этой привязки, затем sendMessage отправляет ForceReply. Полученный message_id записывается условным UPDATE по прочитанному состоянию. Ответ разрешён только после сохранения точного ID и совпадения с Telegram reply_to_message.message_id.

Ошибочный/потерянный ответ sendMessage не считается подтверждённой доставкой. Ошибка записи ID не делает вопрос пригодным для ввода. Если диалог успел измениться, запоздалый ответ Telegram не привязывается к новому состоянию.

Продолжение или повтор вопроса после ошибочного значения меняют ревизию шага и очищают старый ID перед отправкой. Старые ответы перестают подходить. Само подтверждение создания товара при /input не меняет ревизию: ключ восстановления 0022 сохраняется. Выбор раздела проверяет manage_categories повторно; роли не расширены.

Команды нижней клавиатуры обрабатываются до текстового ввода. В DEV зарегистрирована шестая команда /input и доставлена постоянная клавиатура с «Продолжить ввод». Рабочие боты не перенастраивались.
