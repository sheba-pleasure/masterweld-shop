# Редактор проверенных характеристик

Подключён в DEV 06.11.2026, сборка 7b5af37f7739466130ea2cbb257c68a32dc0b758, схема 0020. Настоящие БД и Telegram API прошли учебную проверку изменения/повтора/отката; входящие действия симулированы. Ручная визуальная проверка не выполнена. Реальные товары, исторический Cloud и main не изменялись.

## Работа сотрудника

В служебном боте откройте товар → «Редактировать» → «⚙️ Проверенные характеристики». «📄 Прежнее описание характеристик» остаётся отдельным текстовым полем и не становится подтверждённой технической карточкой.

1. Начните от опубликованной карточки. Владелец также может явно выбрать одно из десяти последних предложений товара.
2. Выберите семейство по паспорту. Смена семейства с заполненными значениями требует подтверждения очистки черновика.
3. Выберите характеристику и режим. Для нескольких условий одного параметра добавьте новое значение; для исправления выберите существующее.
4. Ответьте именно на сообщение-вопрос бота. Используйте указанную единицу; числа можно вводить с десятичной запятой, списки — через точку с запятой. «Нет» и «нет подтверждённых сведений» различаются.
5. Заполните обязательные условия измерения и источник. Бот спрашивает организацию, точную модель, название документа, HTTPS-ссылку, страницу/раздел, дату проверки. Ссылка не доказывает достоверность: документ проверяет сотрудник.
6. Посмотрите значения и источники. Продавец готовит предложение на проверку. Владелец может подготовить подтверждение для витрины; источник поставщика/исследование для этого недостаточен.
7. В предпросмотре сравните «Было» и «Станет», затем подтвердите. Подтверждение характеристик само по себе не публикует товар и не снимает исключение из ассортимента.

Черновик живёт 24 часа, предпросмотр — 30 минут. «⚙️ Продолжить характеристики» или /technical восстанавливает текущий шаг, а после потерянного результата показывает последнее состояние. Ответ на старый вопрос или старая кнопка не меняют новый шаг. /cancel предлагает отменить черновик. Переход к карточке сохраняет его; возвращение к началу черновика отбрасывает только незавершённое поле.

На одного сотрудника допускается один активный черновик. Другой товар не заменяет его молча. При конфликте с чужой правкой сохранённый черновик нужно сверить, отменить и начать заново от актуальной карточки. Бот не подставляет новую версию автоматически.

После применения владелец может запросить откат и подтвердить его. Срок — 7 дней; последующие изменения блокируют откат. Продавцу кнопка отката не предлагается: опубликованную карточку восстанавливает владелец.

## Границы пилота

40 определений и 69 привязок, выбранных из исследовательского пакета. В выборе доступны только семейства с пилотными полями. Полный словарь из 374 полей, массовое заполнение SKU, автоматический подбор совместимости и перенос реальных данных не выполнены. Новый файл источника не загружается: используется ссылка; существующий SHA256-источник можно выбрать из карточки.

Проверка предложения показывает последние десять ревизий конкретного товара; это пока не отдельная общая очередь задач. Настоящая визуальная проверка на телефоне не заменяется серверным тестом.

## Реализация и безопасность

- Добавочная миграция 0020: закрытая technical_editor_sessions и SECURITY DEFINER RPC bot_technical_editor. Прямые права таблицы отозваны также у service_role.
- Право edit_products проверяется до доступа к сервису; SQL повторяет проверку актуального сотрудника под блокировкой. Только разрешённый сотрудник в личном чате; покупательский обработчик не подключается.
- На старте фиксируются исходная версия и опубликованный документ. Параллельное сохранение использует ревизию сессии. Предпросмотр вызывает существующий 0019 с исходной версией.
- Создание предпросмотра и изменение состояния сессии атомарны; применение/откат и переход состояния тоже атомарны с аудитом. Повтор подтверждения возвращает прежний результат.
- Сообщение-вопрос привязано к реальному Telegram message_id. Неопределённая доставка не повторяется автоматически: /technical восстанавливает шаг и задаёт новый вопрос. Telegram не гарантирует идемпотентную отправку сообщения.
- В логах аудита только идентификаторы, ревизия и фаза; значения, секреты и SQL-ошибки не выводятся.
- Формат ForceReply сверяется с [официальным Telegram Bot API](https://core.telegram.org/bots/api#forcereply).

## Проверки и откат

Unit-тесты проверяют типы, диапазоны, условия, источники, права, старые ответы/кнопки, потерянный ответ Telegram и ограничения callback. Изолированный PostgreSQL проверяет CAS, владение, отказ при отзыве прав, устаревшую основу, атомарный аудит, повтор применения, откат, перезапуск и восстановление dump.

Оператор: python3 ops/dev/apply-technical-catalog.py --editor-sessions. Только проверенная DEV-БД, чистый коммит, отдельный backup, репетиция на восстановленной копии и контроль неизменности всех старых таблиц.

Откат приложения к предыдущей DEV-сборке сохраняет добавочную таблицу; не удаляйте её и аудит ради отката. Старый интерфейс не показывает новый черновик, но данные остаются. Production требует отдельной проверки и разрешения «обнови main».
