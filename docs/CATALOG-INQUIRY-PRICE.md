# Импорт карточек без продажной цены

Предложение 0045 позволяет подготовить каталог из прайса, в котором нет продажных цен. По умолчанию импорт по-прежнему требует цену для нового товара. Сотрудник с правами импорта и просмотра закупочных цен может явно включить режим «Цена по запросу» для своего импорта, затем прочитать новый предварительный результат и отдельно подтвердить применение.

Контракт существующего RPC `bot_catalog_import`: `p_op='inquiry_price'`, `p_id=<свой импорт>`, `p_payload={"enabled":true}`, `p_revision=<прочитанная ревизия>`. Выключение передаёт `false`. Результат и операция `source` возвращают `inquiry_price:boolean`. Изменение настройки сбрасывает предварительный результат, увеличивает ревизию и создаёт запись аудита. Повтор того же значения с текущей ревизией ничего не меняет. Настройка недоступна после применения или истечения срока.

Режим разрешает отсутствие поля `price` только у нового товара: цена сохраняется как SQL NULL, статус — `draft`, решение об ассортименте — `review`. У существующего товара отсутствие цены оставляет прежнее значение. Импорт не меняет существующий статус и решение об ассортименте, не возвращает исключённые товары в продажу. Явные NULL, ноль, отрицательные значения, строки и дроби с лишними знаками в колонке цены остаются ошибками.

Документный импорт сохраняет проверку строк, владельца, источника и модели. Настройка не подтверждает строки автоматически и не заменяет отдельное подтверждение применения. Технические характеристики и фотографии этим изменением не утверждаются.

## Публикация, заказ и отмена

Товар с NULL нельзя опубликовать через штатное подтверждение, даже если есть название и фотография. Отмена скрытия в ассортименте также проверяет наличие цены. После публикации нельзя отменой изменения цены восстановить NULL: операция завершается ошибкой, опубликованная карточка и цена сохраняются. Для черновика подтверждённое изменение NULL → цена и его отмена используют прежние квитанции и проверку исходного значения.

Расчёт заказа в приложении отвергает NULL. Дополнительный SQL-триггер блокирует вставку заказа с таким товаром и удерживает блокировки товаров, чтобы цена не изменилась между проверкой и записью. Ранее сохранённые квитанции заказа продолжают работать по существующему пути.

Типы и отображение приложения допускают NULL без преобразования в ноль. Защитное отображение показывает «Цена по запросу», обращение по почте с артикулом и названием и телефон вместо покупки. Это не разрешает публикацию импортированных черновиков.

## Установка только в DEV

Целевое состояние — установленная база 0000–0043 плюс самостоятельная 0045. Предложение 0044 не требуется и этим переходом не устанавливается; runner отвергает его служебные таблицы и маркер учебного архива.

Файл: `docs/proposals/0045_catalog_inquiry_price.sql`.

SHA-256: `29b2bb49b7738c1694aea26192fc1a188c68109df43c222c7d718ead8479da1b`.

`ops/dev/apply-inquiry-prices.py` требует чистый точный commit, соответствующий образ и capability `mw.capabilities.inquiry-price=1`. Источник берётся из текущего worktree; состояние и секреты — из канонического DEV-каталога. До перехода выполняются изолированная репетиция и проверка кандидата, затем штатная остановка обработчиков. В одной транзакции проверяются исходные функции 0043, все старые значения и права; записываются две квитанции — SQL и связь commit/образ. Существующие товары, цены, статусы, история и права не изменяются. Новые реальные резервные копии, загрузки и расписания не создаются.

После неопределённого результата сначала используется `--check`. Нельзя повторять установку, удалять журнал или сбрасывать квитанции. `--finish <EXACT_SHA>` продолжает существующий переход только после проверки его результата. Предыдущий несовместимый образ нельзя запускать над новой схемой; частичная схема блокирует запуск.

На момент подготовки этого документа выполнены локальные проверки исходников и изолированная SQL-репетиция. Установка в действующую DEV-базу этим документом не подтверждается; фактические commit, образ, квитанции и состояние фиксируются в `STATUS.md`. Main, production и действующие товары этой подготовкой не изменены.
