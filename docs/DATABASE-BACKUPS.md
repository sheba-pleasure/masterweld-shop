## Что делает одна копия

1. Проверяет имя контейнера, среду и идентификатор базы.
2. Открывает согласованный снимок только для чтения. Контрольные суммы таблиц и pg_dump используют один снимок; новый заказ во время копирования не делает проверку противоречивой.
3. Сохраняет дамп, определения ролей без паролей, контрольные суммы, права таблиц/функций и RLS, автономный проверяющий скрипт и инструкцию.
4. Восстанавливает дамп в новый PostgreSQL без сети и опубликованных портов. Сверяет строки, идентификатор, права таблиц/функций и RLS до и после перезапуска.
5. При --offsite загружает новый архив на Яндекс.Диск, скачивает его обратно, сверяет SHA-256 и повторяет восстановление именно скачанного файла.
6. Записывает успешный результат только после завершения всех запрошенных этапов. Одновременный запуск для той же среды блокируется.

Действующая база при восстановлении не открывается. Сохранённые sent/uncertain/sending/pending и результаты заказов/правок восстанавливаются без сброса. Копии не запускают приложение, обработчик Telegram или рассылку.

## Команды администратора

Проверить, есть ли успешная внешняя копия DEV моложе 26 часов:

```sh
python3 ops/standalone/database-backup.py status dev
```

healthy=true означает свежую копию со скачиванием и восстановлением. healthy=false или ошибка требуют разбора. Проверка не работает в фоне и не посылает уведомлений.

Ручная проверенная копия:

```sh
python3 ops/standalone/database-backup.py backup dev --offsite
```

Для рабочей среды предусмотрен отдельный аргумент production. Он читает только её идентификатор из защищённой конфигурации и обращается только к mw-prod-db/masterweld_production. Включение рабочего расписания входит в release review; режим DEV его не активирует.

## Расписание DEV

Подготовлен установщик ops/standalone/install-dev-backup.py. Он принимает только чистый коммит, сохраняет точную версию скрипта в ops/.state/backup-runners/<SHA>/ и создаёт две пользовательские systemd-единицы:

- masterweld-dev-database-backup.service;
- masterweld-dev-database-backup.timer.

Изменения рабочей ветки не подменяют установленный скрипт. Существующие отличающиеся единицы установщик по умолчанию не перезаписывает. Для проверенного обновления собственного скрипта нужен --replace-runner <прежний полный SHA>; обе единицы должны быть неактивны, а их содержимое — точно соответствовать прежней установленной версии. Старый скрипт сохраняется. Установщик не включает расписание и не запускает службу автоматически.

Время: ежедневно 05:00 МСК (02:00 UTC), с задержкой до пяти минут. Persistent=true позволяет выполнить пропущенный запуск после возвращения пользовательского менеджера. Одновременных копий нет; автоматических повторов после неопределённой ошибки загрузки нет.

После успешной первой проверки через службу расписание включается отдельно:

```sh
systemctl --user start masterweld-dev-database-backup.service
systemctl --user enable --now masterweld-dev-database-backup.timer
systemctl --user list-timers masterweld-dev-database-backup.timer
```

Результат запуска и причина ошибки:

```sh
systemctl --user status masterweld-dev-database-backup.service
python3 ops/standalone/database-backup.py status dev
```

Наличие файлов единиц ещё не доказывает работающий таймер. Фактическое включение и первая копия фиксируются отдельно по результатам проверки.

## Где искать

Локально: ops/.state/database-backups/dev/<время>-<случайный ID>/; для production — отдельная папка. Файлы 0600, каталоги 0700, вне Git и сайта. latest.json хранит последний сохранённый результат, а каждый запуск — свой status.json.

На Яндекс.Диске: в существующей папке «Мастер Сварщик — резервные копии» создаётся отдельная подпапка DEV_database_<время>-<ID> или PRODUCTION_database_<время>-<ID>. В ней database.tar.gz и verification.json после успешной проверки. Публичные ссылки не создаются. Старые папки не перезаписываются и не удаляются.

При ошибке загрузки может остаться неполная папка без verification.json. Она не считается подтверждённой внешней копией. Локальный архив сохраняется для разбора.

Автоматического удаления копий пока нет. Администратору нужно контролировать место; перед запуском проверяется свободный 1 ГиБ. Это начальная политика хранения, а не бессрочная гарантия наличия места.

## Проверка скачанного архива

Скачать архив и verification.json в закрытую папку, сверить SHA-256. Не распаковывать поверх проекта. Для проверки существующим доверенным скриптом:

```sh
python3 ops/standalone/database-backup.py restore /полный/путь/database.tar.gz --output /новая/закрытая/папка
```

Нужны Python 3.10+, Docker и локальный образ postgres:17.6-alpine. Новая папка результата должна отсутствовать. Архив проверяется на контрольные суммы, допустимые имена, повторные пути, ссылки и размеры. Команда создаёт только временный контейнер без сети, затем удаляет его вместе с томом.

Это репетиция восстановления. Она не умеет перезаписывать рабочую базу. Реальный аварийный переход требует отдельного плана с остановкой записи, восстановлением конфигурации и проверкой уведомлений.

## Сверка разрешений

После pg_dump/restore явно заданные стандартные права владельца могут быть записаны как ACL=NULL. Для сравнения раскрываются стандартные разрешения через acldefault, а выдачи через aclexplode сортируются. Владелец, получатель, вид права и возможность передачи права продолжают сравниваться. Дополнительный доступ не игнорируется. Семантика функций: [PostgreSQL 17](https://www.postgresql.org/docs/17/functions-info.html#FUNCTIONS-ACLITEM-FN-TABLE).

## Границы

В архиве полная самостоятельная база и роли без паролей. Файлы фотографий, токены, пароли, конфигурация приложения, Docker-образы и сам сервер не включены. Для полного восстановления магазина они нужны отдельно. Восстановление на другом физическом сервере пока не испытано.

Восстановление проверено в закрытой учебной базе, на скачанной копии настоящего DEV и отдельной пустой production-БД. Регулярность production, свежая копия после переноса реального каталога и полнота восстановления всего магазина остаются частью подготовки выпуска.

Рабочий выпуск остаётся закрытым: [порядок запуска](LAUNCH-CHECKLIST.md).
