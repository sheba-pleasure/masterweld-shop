# Выпуски интернет-магазина «Мастер Сварщик»

Две команды владельца: **«Выпускай»** и **«Откати»**. Больше ничего не требуется.

Путь: задача → отдельная ветка в DevSpace или на компьютере → проверки → PR в GitHub `dev` → PR `dev → main` (проверка `verify`) → «Выпускай» → merge → сборка образа точного SHA → новый слот рядом со старым → переключение → проверка → при сбое автооткат.

## Важные ограничения
- **Защита ветки `main` недоступна**: на бесплатном тарифе GitHub для private-репозитория API отвечает 403. Поэтому **автоматический выпуск по любому push в `main` запрещён**. Сборка и выпуск запускаются только вручную после явного «Выпускай» в чате и проверки merge PR + успешного `verify`.
- Единый протокол для компьютеров и агентов: [COLLABORATION.md](COLLABORATION.md). GitHub `dev` — общий источник. Изолированные task-ветки → PR в `dev`; не выгружать старые полные снимки. Lovable необязателен; перед его использованием проверить синхронизацию. В `main` напрямую не пишем, force push не делаем.
- **БД не откатывается автоматически.** Скрипты не запускают миграции и не меняют данные; необратимую миграцию откат приложения не отменяет.
- Историческая проверка выпуска не подтверждала подключённый production. Наличие DevSpace не доказывает выпуск магазина; состояние контейнеров, ключей и SHA проверять перед каждым выпуском.

## Проверки
- В Lovable: `npm test`, `npm run build`, сборка для сервера (`NITRO_PRESET=node-server`, вне песочницы Lovable → `.output/server/index.mjs`), `bash ops/tests/release-synthetic.sh`.
- GitHub Actions (`.github/workflows/verify.yml`, push в `dev` и PR в `main`): то же самое; `lint` — только справочно (~407 старых ошибок). Секретов и деплоя нет.

## «Выпускай» (на сервере, после merge)
1. `CONFIRM_BUILD=yes ops/build-approved.sh <SHA>` — проверяет merge в `main` + `verify`, собирает образ из `git archive <SHA>` во временной папке (ветки и рабочие файлы не меняются). В образ идут только публичные `VITE_SUPABASE_*` из `ops/.secrets/build-public.env` (права 600).
2. `ops/release.sh <SHA>` — сначала все проверки (SHA, ключи `ops/.secrets/shop.env` 600, вход, GitHub, образ, состояние), только потом действия: новый слот → health + smoke + `noindex, nofollow` → переключение → smoke. Сбой после переключения → возврат прежнего слота; при самом первом выпуске → вход отвечает 503, успех не объявляется.

## «Откати»
- `ops/rollback.sh` без аргумента: возвращает сохранённый предыдущий слот+SHA. Работает **без интернета и без образа**: по локальному журналу утверждённых выпусков `ops/.state/approved` (обычный файл, без записи для чужих), меткам SHA существующего контейнера и smoke. Если контейнера уже нет — отказ с объяснением, восстановление не делается. SHA-аргумент необязателен и должен совпасть с сохранённым.

## Сервер (blue/green, только 127.0.0.1)
- Слоты `a` = 18081, `b` = 18082; вход 18080 (`mw-shop-gateway`, отдельный nginx; без рабочего слота отвечает 503). Caddy, VPN, firewall, DNS не трогаются.
- release, rollback и build используют общий замок `ops/.state/release.lock`: параллельная команда сразу получает отказ.
- Первый запуск входа: `CONFIRM_SERVER_CHANGE=yes ops/gateway-up.sh` — только по разрешению владельца.
