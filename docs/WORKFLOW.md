# Выпуски интернет-магазина «Мастер Сварщик»

Коротко: разработка в Lovable → проверки → копия кода в GitHub `dev` → PR `dev → main` → владелец пишет «Выпускай» → сервер проверяет новый образ рядом со старым → переключение → проверка → при сбое автооткат.

## 1. Разработка и проверки (Lovable)
- `npm test`, `npm run build`, сборка для сервера (см. п. 5). `npm run lint` пока с долгом (~407 ошибок) — только справочно.

## 2. Копия кода в GitHub
- Репозиторий: `sheba-pleasure/masterweld-shop` (private). Ветка `dev` — копии из Lovable, `main` — утверждённое.
- **Встроенная синхронизация Lovable (Git Sync) не включена.** Изменения в Lovable сами в GitHub не попадают: после каждого обновления агент выгружает полный снимок в `dev` (без `.env` и ключей), в сообщении коммита — Lovable SHA. В `main` напрямую не пишем, force push не делаем.
- На push в `dev` и PR в `main` запускается `.github/workflows/verify.yml` (тесты, обе сборки, тесты скриптов выпуска; lint — advisory). Секретов и деплоя в нём нет.

## 3. «Выпускай»
- Владелец одним сообщением «Выпускай» разрешает merge PR `dev → main` и выпуск именно этого SHA. Без этого сообщения выпуска нет.

## 4. Сервер (blue/green, только 127.0.0.1)
- Слоты: `a` = 127.0.0.1:18081, `b` = 127.0.0.1:18082; постоянный вход — 127.0.0.1:18080 (`mw-shop-gateway`, отдельный nginx). Существующий Caddy, VPN, firewall, DNS не трогаются; внешний доступ — отдельное решение.
- Образ: `docker build --build-arg GIT_SHA=<SHA> ... -t masterweld-shop:<SHA> .` из checkout ровно этого SHA.
- `ops/release.sh <SHA>`: проверяет полный SHA, что он в `main` через смерженный PR и что `verify` успешен (GitHub API, `GITHUB_TOKEN` только для чтения в окружении), наличие образа с этой меткой → запускает неактивный слот → health + smoke + `noindex, nofollow` → переключает вход → smoke → при сбое возвращает прежний слот (код 2). Предыдущий контейнер сохраняется.
- «Откати» → `ops/rollback.sh <SHA>`: только на сохранённый предыдущий утверждённый слот+SHA.
- Серверные ключи — только в `ops/.secrets/shop.env` (chmod 600), состояние — `ops/.state/`; оба в `.gitignore`.
- **БД:** скрипты не запускают миграции и не меняют данные. Миграции применяются отдельно и только по отдельному разрешению; необратимую миграцию откат приложения не отменяет.
- Первичный запуск входа: `CONFIRM_SERVER_CHANGE=yes ops/gateway-up.sh` — только после разрешения владельца.

## 5. Сборка вне Lovable
- В песочнице Lovable `NITRO_PRESET` игнорируется (сборка всегда для Lovable-хостинга, превью не ломается). Вне Lovable (Docker/CI, без `LOVABLE_SANDBOX`/`DEV_SERVER__PROJECT_PATH`) `NITRO_PRESET=node-server npx vite build` даёт `.output/server/index.mjs`; запуск `PORT=3000 node .output/server/index.mjs`.
- Тесты скриптов выпуска: `bash ops/tests/release-synthetic.sh` (подмена docker/curl, без сервера).
