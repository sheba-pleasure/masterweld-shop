## Как теперь работать

**Документ:** отправьте файл → откройте результат → выберите таблицу → исправьте ошибки → проверьте или пропустите каждую строку → передайте в предпросмотр импорта → проверьте колонки и изменения → отдельно подтвердите импорт. Новые товары будут черновиками. Для публикации требуется отдельное решение.

Если неверно распознана таблица, нажмите **«Исправить таблицу»**. Можно исправить заголовок, добавить пропущенный товар и разделить склеенную строку на несколько товаров. Оригинал сохраняется. Изменённые строки нужно проверить заново. Из неприменённого импорта можно вернуться к документу без повторной загрузки.

**Ассортимент:** выберите группу → отметьте товары → выберите действие → прочитайте последствия → подтвердите. **«Убрать»** снимает отметку выбора. **«Не продаём»** скрывает товар; повторный импорт его не возвращает. **«В ассортимент»** само по себе не публикует товар. Отмена изменений сначала показывает последствия и не перезаписывает последующие правки.

**После ошибки:** используйте кнопку открытия сохранённого результата. Не создавайте тот же импорт или действие заново, пока результат неизвестен. Для незавершённого вопроса есть **«Продолжить ввод»**. Кнопки главного меню работают и в прежних сообщениях ассортимента.

Продавцы работают с карточками, наличием и заказами, видят закупочные цены. Импорт, изменение цен, массовое исключение, публикация и управление доступом остаются ограниченными. Покупатели закупочные цены не видят.

## Что требует следующих данных или отдельного этапа

1. **Проверка людьми.** Владелец и сотрудники проходят знакомый сценарий на своих телефонах. Проверки кода и сформированных сообщений этого не заменяют. Не создавать учебные заказы без учёта всех активных получателей уведомлений.
2. **Прайсы и ассортимент.** После получения файлов проверить реальные артикулы, единицы продажи, цены и наличие; выбрать товары первого запуска. Не выводить цену продажи из закупочной без согласованных правил.
3. **Фотографии.** Нужны исходные файлы или доступ к ним. Перенос старых изображений и новая загрузка фото не закончены. Ссылки в прежнем снимке не заменяют сами изображения.
4. **Автоматический поиск и генерация.** Нужны API-аккаунт и согласованные расходы. Подключение провайдера, поиск, генерация и их проверка — отдельная реализация поверх подготовленного процесса. До этого использовать проверенные источники и ручные решения; не обещать автоматическое наполнение.
5. **Настройки рабочего магазина.** Нужны утверждённые контакты, получение/доставка, способ оплаты и документы магазина. Онлайн-оплата, кабинет, CRM/почта не считаются готовыми.
6. **Исторические данные.** Сверить изменения старого каталога после снимка 06.11.2026, разрешить неоднозначные артикулы, утвердить перенос. Решение по двум старым заказам открыто; они не включаются в новую очередь.
7. **GitHub CI.** Исправить оплату/лимит в аккаунте GitHub. После подтверждённого исправления один раз проверить актуальный HEAD. Последний изученный отказ — run 43082222237, до запуска runner. Локальные результаты не заменяют успешный GitHub CI для слияния и выпуска.
8. **Рабочий запуск.** Только после «Обнови main»: свежая проверка фактической схемы, миграций, домена/HTTPS, рабочих ботов, разрешения точного SHA и пути GitHub → сервер. При блокерах выпуск остановить. Новые резервные копии и выгрузки по действующему указанию не создавать.
