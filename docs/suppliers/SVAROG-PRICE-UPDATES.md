## Как пользоваться

1. Открыть частный `catalog-review-v2.html`: поиск по коду/названию, группы товаров, фильтры вопросов, дублей и формул, карточка с листом и строкой источника. Суммы подписаны как цены поставщика, а не цены магазина. Отчёт работает локально без сетевых запросов.
2. Разобрать вопросы и сверить товары с существующим каталогом. `rows-requiring-review.csv` содержит 100 исключённых строк, их происхождение и причины исключения; оригинальные значения всех 2008 строк остаются в `snapshot.json`.
3. Для отдельного предпросмотра использовать `draft-inquiry-import.csv` с 1908 строками. Сопоставить только `sku` и `title`; остальные колонки — сведения об источнике и ограничениях. Для новых товаров явно выбрать «Цена по запросу» в поддерживающем этот режим штатном импорте. Сам CSV не включает этот режим.
4. Проверить **каждое совпадение SKU с существующей карточкой**: поставщика, модель, название и ручные правки. Коды точные, без префикса, с ведущими нулями. Штатный импорт сопоставляет SKU; колонка `supplier` не является автоматической проверкой принадлежности. Если совпадение не установлено, импорт не применять. Наличие подготовленного CSV не разрешает заменять ручные правки.
5. Применять только через штатный owner-bound предпросмотр и отдельное подтверждение, когда соответствующий путь доступен в целевой среде. Новые товары должны оставаться черновиками «На разбор». Публикация — отдельное решение.

Цены, закупочные затраты, бренд, остатки и категории в CSV не назначаются. Названия не обрезаются ради прохождения импорта. Формат CSV: UTF-8 с BOM, разделитель `;`, поля в кавычках. При просмотре в Excel колонку `sku` нужно читать как текст. Экранирование потенциальных формул в CSV не меняет исходник в снимке.

## Контракт нормализатора и повторных прайсов

Код: `ops/suppliers/svarog_price_updates.py`. Используется стандартная библиотека Python; сеть и секреты каталога не нужны. Поддерживаются известные листы и заголовки прайса Сварог; неизвестная структура требует проверки. Привязки к одному SHA нет.

- `parse_workbook(raw, filename)` сохраняет исходные значения ячеек, числовой формат, лист/строку, явные модель и упаковку, признаки скрытия и причины проверки. Ведущие нули сохраняются из текста или явного нулевого числового формата; недостоверный формат помечается.
- Ключ предложения строится из поставщика, точного кода, явно указанной модели и упаковки. Номер строки, цена и SHA файла не входят в ключ. Модель по похожему названию не угадывается; минимальная партия не приравнивается к упаковке или остатку.
- Формулы, включая shared formula, не исполняются. Их кэш не используется как значение: сумма остаётся неизвестной; формула и хеши сохраняются для проверки.
- Все извлечённые цены поставщика непроверенные. Цена магазина, закупочная цена и остаток не выводятся из них автоматически.
- `compare_snapshots(previous, current)` возвращает новые, изменённые, пропавшие, неизменённые предложения и конфликты. Все строки дублей сохраняются. Пропавший товар имеет действие `keep_current_catalog`; автоматического скрытия нет. Смена идентичности требует сверки.
- `intake(original, state, expected_previous=None)` сохраняет исходные байты и неизменяемые результаты по SHA-256. Квитанция содержит `requires_review=true`, `catalog_changed=false`, исходный SHA и каталог снимка.
- `export_review_csv(snapshot)` возвращает `draft_csv`, `review_csv` и `manifest`; `write_review_export(snapshot, directory)` сохраняет их. Manifest содержит `draft_only=true`, `publication_authorized=false` и `supplier_collision_check=not_performed`.
- `svarog_report.build_report(state, source_sha)` проверяет квитанцию и контрольные суммы и создаёт `catalog-review-v2.html`. Старый `catalog-review.html` сохранён неизменным после исправления доступного имени диалога.

`current.json` означает **последний успешно разобранный источник**, а не последний одобренный прайс или действующие цены. Дата доставки письма не устанавливает дату действия прайса.

Частные каталоги создаются с 0700, файлы — 0600. Неблокирующий `flock` исключает параллельную запись; каталог снимка и указатель публикуются атомарными операциями. Повтор тех же байтов возвращает прежнюю квитанцию без повторной нормализации. Повтор старого SHA не откатывает более новый указатель. Повреждение сохранённых контрольных сумм блокирует чтение.

Если запись остановилась после сохранения снимка, но до обновления указателя, повтор того же SHA может завершить запись, только пока прежний указатель не изменился. Новый файл при незавершённом переходе получает `RECOVER_PREVIOUS_INTAKE_FIRST`. Не удалять квитанции/снимки ради повторного запуска. `--expected-previous` позволяет закрепить ожидаемую предыдущую версию; её нельзя подменять свежей только ради обхода конфликта.

## Команды

Повторный приём исходного файла использует прежнюю квитанцию; CSV/HTML при совпадении содержимого остаются прежними. Различающееся содержимое существующего производного файла не перезаписывается.

```bash
cd /home/codex/projects/masterweld.ru
SVAROG_STATE=/home/codex/projects/masterweld.ru/ops/.state/suppliers/svarog-mail-bridge/price-updates
SVAROG_SHA=f63d386248cdec16cbf9dcfeae3c9b003e0ca7267326f44c3a15ff96b7bbd74e
python3 -B ops/suppliers/svarog_price_updates.py \
  --input /home/codex/projects/masterweld.ru/ops/.state/suppliers/svarog-mail-intake/2026-11-12-f63d386248cd/original.xlsx \
  --state "$SVAROG_STATE" --export-csv
python3 -B ops/suppliers/svarog_report.py \
  --state "$SVAROG_STATE" --sha "$SVAROG_SHA"
```

Для следующего файла передать его реальный частный путь в `--input`, сохранив тот же `--state`. При необходимости указать фактически прочитанный `--expected-previous SHA`. Затем строить отчёт по `source_sha256` новой квитанции. Сохранение нового прайса создаёт проект сравнения, не обновление магазина.
