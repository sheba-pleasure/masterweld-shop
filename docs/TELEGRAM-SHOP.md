# Два бота и один магазин

## Назначение

- **@msvarbot — покупателям.** Кнопка «Открыть магазин» открывает сайт внутри Telegram. Тот же каталог, поиск, карточки, корзина и оформление.
- **@masterweldermanagerbot — сотрудникам.** Заказы, наличие, карточки, ассортимент и импорт по правам сотрудника. Закупочные цены покупателям не доступны.
- **@testmw639bot — только DEV.** Команда /shop показывает кнопку учебного магазина. Рабочие токены в DEV не устанавливаются.

Покупательский бот не принимает команды управления. Сотрудник работает через свою учётную запись; /start показывает ID без автоматической выдачи доступа. Валентина и Светлана будут подключены после получения их ID.

## Что означает «зеркало»

Сайт и магазин внутри Telegram используют одну витрину и один backend соответствующей среды. Копий каталога и двустороннего переноса нет. Скрытие или исключение закрывает товар для обоих входов. Цена и наличие повторно проверяются сервером при заказе; заказ попадает в общий список сотрудников и действующую очередь уведомлений.

Уже открытый экран может показывать кеш до обновления; это не разрешает купить скрытый товар или молча принять новую цену. Корзина хранится в текущем браузере: между браузером телефона, компьютером и Telegram автоматически не переносится. Общий личный кабинет и история покупателя пока не реализованы.

Mini App использует Telegram SDK только для готовности окна, кнопки назад и безопасных отступов. Данные запуска не дают авторизацию или права. Если позже понадобится личный кабинет, потребуется отдельная серверная проверка initData. Сейчас оформление такое же, как на публичном сайте: имя и телефон.

## Технические границы

- Сотрудники: /api/public/telegram/webhook, TELEGRAM_*.
- Покупатели: /api/public/telegram/customer, CUSTOMER_TELEGRAM_*.
- Разные bot ID, токены и webhook-секреты; перекрёстный секрет отвергается.
- Миграция 0016: telegram_bot_updates с ключом (bot_id, update_id). Историческая telegram_updates остаётся барьером повторного выполнения старых служебных событий.
- Получение webhook ограничено 256 КиБ. Непонятный результат после обработки не сбрасывает запись, чтобы не повторить изменение.
- Рабочая конфигурация не может подменить тестового бота: runtime сверяет окружение, ID, username через getMe и самостоятельную базу.
- Ответы покупательского бота не используют service-role чтение сотрудников, закупок или заказов. Запись заказа остаётся в существующем createOrder.

## Переход после команды «обнови main»

Сначала свежая проверка выпуска, production-БД и миграций 0014–0016, перенос и сверка данных, рабочий домен, backup/restore, выпуск и откат. Отдельно проверить и разрешить рабочие уведомления: worker сейчас ограничен DEV.

Затем подключить защищённые параметры bots.env к рабочей конфигурации, повторить getMe/getWebhookInfo, сверить отсутствие другого polling и список ожидающих событий. Старый webhook сотрудников заменяется только в согласованное окно перехода; pending updates не удалять. Зафиксировать прежний обработчик и последствия возврата к старой базе.

У покупательского бота настроить команды start/shop/contacts/help и меню web_app «Магазин» с URL https://shop.masterweld.ru/?miniapp=1. Webhook каждого бота направить только на его маршрут с собственным secret_token. Проверить настоящий /start, открытие Mini App, покупку и обработку одного заказа сотрудником. Эти действия не считаются выполненными по наличию кода.
