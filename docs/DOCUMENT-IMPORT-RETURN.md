# Исправление документа после предпросмотра

## Для администратора

1. В настройке импорта, предпросмотре или сверке моделей нажмите **«✏️ Исправить документ…»**.
2. Прочитайте последствия и нажмите **«✏️ Да, перейти к исправлению»**. Старый предпросмотр отменится; товары не изменятся. Бот сразу покажет текущий разбор.
3. Исправьте ячейки или заголовки, добавьте пропущенный товар, разделите ошибочно объединённую строку либо пропустите ненужный товар.
4. Проверьте изменённые строки. Изменение заголовка требует повторной проверки затронутых строк. Уточните модель, если исправление сделало её прежнее подтверждение неактуальным.
5. Передайте проверенные строки в новый импорт. Проверьте колонки, разделитель сумм и новый предпросмотр. Только отдельное подтверждение применяет изменения.

Повторная загрузка исходного файла не нужна. Его оригинал, исправления и история остаются сохранены. Новый импорт получает отдельный номер; прежний остаётся отменённым.

Если передумали, выберите **«Остаться в импорте»** на экране подтверждения. Если открыт другой вопрос, сначала завершите его через /input или отмените ввод через /cancel. Возврат не стирает незавершённые ответы.

При обрыве связи откройте /import и прежний импорт. Кнопка **«Открыть документ для исправления»** покажет текущее состояние. Повтор старой кнопки возврата не отменяет следующий импорт.

## Ограничения

Возврат доступен только владельцу документа с действующими правами импорта и просмотра закупочных данных, в личном чате. Продавцам эти права не добавляются. Прямой CSV без распознанного документа сохраняет прежний порядок работы.

Можно вернуть настройку, предпросмотр, в том числе просроченный, и отменённый неприменённый импорт. Применённые импорты и импорты после отката этим действием не открываются. Для применённого импорта действует отдельный конфликтобезопасный откат.

Возврат не импортирует, не публикует, не меняет товары, цены, заказы и решения «Не продаём». Неизменённые подтверждения строк сохраняются; изменённые требуют повторной проверки. Автоматическое обогащение не запускается.

## Серверная защита

Миграция 0032 добавляет закрытую квитанцию document_import_returns и операции return_prepare/return_confirm в существующий проверяемый RPC. Подтверждение связано с точными версиями импорта и разбора. Подготовка ничего не меняет.

Отмена прежнего импорта, снятие активного указателя, квитанция и аудит выполняются в одной транзакции. Исторические document_import_origins, замороженный source и решения о моделях сохраняются. Старые кнопки после нового импорта только восстанавливают результат. Возврат и применение используют одинаковую последовательность блокировок.

Кнопки Telegram ограничены 64 байтами; тексты и транспорт используют существующие обработчики. Новые внешние API не подключены.

## Проверка и развёртывание

ops/tests/document-import-return.py проверяет настоящую изолированную PostgreSQL: права, версии, подготовку без записи, атомарный отказ, параллельные повторы, сохранность исходников, повторную проверку строки, старую кнопку после нового импорта и перезапуска, просроченный/отменённый импорт, запрет применённого импорта и импорта после отката и конкуренцию применения с возвратом.

Vitest проверяет переходы, подписи, длину кнопок, передачу обеих версий, права и восстановление неизвестного результата. ops/dev/verify-document-import-return.ts предназначен для настоящего DEV-парсера, БД и доставки только владельцу; входящие действия симулируются, Telegram-клиент не просматривается.

ops/dev/apply-document-import-return.py применяет только 0032 в DEV через проверку идентичности, прежнего определения RPC, сохранности всех прежних публичных колонок и закрытых прав. Используется уже готовый проверенный снимок; новый цикл резервирования не запускается. Если данные после снимка изменились, runner останавливается без обхода проверки.

Фактическая установленная версия и результаты прогона указываются в STATUS.md и docs/VERIFICATION.md. Наличие этого файла само по себе не означает развёртывание. Production и main требуют отдельного решения владельца.
