# Ввод товара в служебном боте

Дата: 06.11.2026. Реализовано только в DEV. Схема остаётся 0000–0021; новая миграция не нужна.

## Порядок работы

У сотрудника один незавершённый ввод. Если уже начато создание товара, изменение поля или выбор раздела, второй запуск сохраняет первый диалог. Ответьте на последний вопрос либо нажмите «Отмена ввода» (/cancel), затем начните другое действие.

Кнопки создания черновика и выбора раздела относятся только к показанному шагу. Кнопки из прежнего диалога не управляют новым. После обновления старые кнопки без привязки отвергаются: отмените оставшийся ввод и откройте действие заново.

Предпросмотр не означает применение. Проверьте «было → станет» и отдельно подтвердите. При сообщении об изменившемся шаге используйте последнее сообщение бота. Ошибка связи с базой показывается отдельно: бот не сообщает об успешной отмене или завершении, если подтверждение не получено.

## Реализация

Каждый сохранённый шаг получает случайный UUID в приватном data._revision существующей bot_editor_states. Кнопки nd:c/nd:x и ec включают эту ревизию. Подмена/повтор прежней кнопки не совпадает с текущей строкой.

Начало диалога проверяет существующее состояние. INSERT не перезаписывает строку; замена завершённой/просроченной строки и продолжение используют условный UPDATE по прочитанным state, data, product_id, expires_at и consumed_at. Новая ревизия отличает даже одинаковые ответы. Истёкший или уже использованный шаг не принимается.

Перед созданием предпросмотра или вызовом bot_create_draft требуется успешное условное потребление именно прочитанного шага. Конкурирующий запрос, получивший ноль строк, останавливается. Возвращённая ошибка базы отличается от конфликта. Права проверяются повторно при продолжении текста; права ролей не расширялись. Защита 0021 от одновременного обычного и технического редакторов сохранена.

## Ограничения

Условное потребление шага и последующая запись pending/создание товара пока отдельные запросы. Сбой между ними может завершить ввод без создания результата; это не атомарная транзакция всего диалога и не гарантия восстановления потерянного ответа bot_create_draft. Перед повторным созданием нужно найти товар по артикулу/названию. Для полной устойчивости требуется единая транзакционная операция с сохранённым результатом.

Обычный текст относится к текущему вопросу; произвольный запоздавший текст без ответа на конкретное сообщение ещё не привязан к ID вопроса. Проверки одновременных запросов не доказывают защиту от такого последовательного позднего ответа.

При откате приложения на прежнюю версию новые фильтры и проверка кнопок исчезнут; одна миграция 0021 не заменяет их. Main, production, рабочие боты и схема базы этим этапом не менялись.
