# Импорт товаров и цен

Рабочий сценарий подготовлен в DEV, в личном чате @testmw639bot. Main и рабочая база этим этапом не обновляются. Начните с учебного файла: реальные прайсы пока не получены.

## Как импортировать

1. Откройте **Меню → Импорт товаров и цен** или отправьте `/import`.
2. Нажмите **Получить учебный CSV**, чтобы посмотреть образец. Для своего файла сохраните таблицу из Excel как **CSV UTF-8**.
3. Пришлите файл боту как документ. Каталог на этом шаге не меняется.
4. Проверьте сопоставление колонок. Нажмите на поле, если нужно выбрать другую колонку или «Не импортировать». Выберите десятичный разделитель цен: запятую либо точку.
5. Нажмите **Построить предпросмотр**. Проверьте количество новых/изменяемых товаров, ошибки и каждую нужную страницу «было → станет».
6. Если всё верно, нажмите **Подтвердить: N товаров**. При любой ошибке весь файл остаётся неприменённым.
7. После применения откройте карточки. Новые товары нужно отдельно разобрать, заполнить, добавить фотографии и проверить перед публикацией.

[Учебный CSV](../public/import-template.csv) содержит вымышленные товар и цены. Его отправка не начинает импорт автоматически. Повторное получение файла также ничего не применяет.

## Формат и поля

Поддерживается CSV UTF-8 с заголовком в первой строке; разделитель — точка с запятой, запятая или табуляция, определяется однозначно. Кавычки и переводы строк внутри ячейки допускаются. Максимум: 2 МБ, 5000 строк данных, 30 колонок. Превышение отвергается, строки не обрезаются.

**XLSX, XLS, PDF и сканы в этом сценарии пока не принимаются.** Существующие вспомогательные извлекатели не объявляются подключёнными. Пока нет настоящих прайсов, произвольные макеты поставщиков, многостраничные книги и формулы не считаются проверенными.

| Поле | Поведение |
|---|---|
| Артикул | Обязателен. Сопоставление по артикулу без учёта регистра и крайних пробелов; нули в начале сохраняются. По названию товары не объединяются. |
| Название | Обязательно для нового товара; 3–200 символов. У существующего меняется только при непустом значении в выбранной колонке. |
| Бренд | Необязателен, до 100 символов. |
| Розничная цена | Рубли, больше нуля, максимум 10 000 000, до двух знаков после выбранного десятичного разделителя. Обязательна для нового товара. |
| Закупочная цена | Отдельное защищённое поле. Не заменяет розничную цену. Автоматическая наценка пока не подключена. |
| Наличие | «да/нет», «есть/под заказ» и однозначные эквиваленты. |
| Количество | Целое 0–1 000 000. Автоматически определяет наличие: ноль — нет, больше нуля — есть. Противоречие с явно заданным наличием блокирует строку. |
| Код раздела | Точный существующий slug раздела; новые разделы автоматически не создаются. Если кода нет, оставьте колонку неиспользуемой. |

Пустые ячейки **не очищают** прежние значения. Неиспользуемые колонки перечислены в настройке; они не меняют каталог. Статус публикации, решение об ассортименте, URL, фотографии, описания и скидочная старая цена этим импортом не задаются.

Цены не умножаются на 100. При изменении розничной цены от 30% и при продаже ниже закупки показывается предупреждение. Оно не заменяет проверку администратором.

Для нового товара без наличия используется «под заказ», без количества — неизвестное количество. Новые товары всегда получают **черновик / На разбор**, даже если в файле есть колонка «Опубликован».

## Исключённые товары и дубли

- **Не продаём** остаётся **Не продаём**, а товар остаётся скрытым после любого импорта.
- Скрытый товар не публикуется автоматически; опубликованный сохраняет публикацию. Импорт меняет только выбранные поля.
- Товары вне файла не скрываются и не удаляются.
- Повторяющийся артикул в файле или несколько совпадений в каталоге блокируют весь импорт. Исправьте неоднозначность вручную.
- Один артикул должен означать один товар магазина. Если поставщики используют одинаковые артикулы для разных товаров, сначала согласуйте систему артикулов; не объединяйте такие строки по названию.
- Если между предпросмотром и подтверждением появился товар с тем же артикулом, импорт остановится без создания дубля.
- Повторное нажатие подтверждения одной операции возвращает сохранённое состояние, не повторяя запись и аудит.

## Как откатить

Откройте `/import`, выберите нужную операцию → **Откатить этот импорт…** → прочитайте последствия → **Подтвердить откат**.

Откат доступен семь дней; его подтверждение действует 30 минут. Прежние импортированные поля существующих товаров восстанавливаются. **Созданные импортом карточки скрываются и отмечаются «Не продаём»**, а не удаляются: возможные заказы, фотографии и история сохраняются. Если позже повторно импортировать эти же артикулы, они останутся исключёнными, пока администратор отдельно не изменит решение об ассортименте.

Если после импорта карточки или закупочные данные менялись, откат целиком остановится. Последующие правки не перезаписываются. Каталог не окажется откатанным наполовину.

## Ошибки и восстановление

Ошибки строк показаны в предпросмотре; подтверждение при ошибках недоступно. Для неверных колонок можно вернуться в настройку, для неверных значений — исправить CSV и отправить заново.

Настройка хранится 24 часа, предпросмотр для подтверждения — 30 минут. Настройки и результат хранятся в БД и переживают перезапуск. `/import` показывает пять последних операций; старые сообщения также содержат кнопки их открытия.

Если связь пропала после подтверждения, сначала откройте последний импорт и проверьте его состояние. Не запускайте повторный импорт вслепую. Старые кнопки подтверждения не применяют новые настройки: версия предпросмотра проверяется сервером.

## Права и хранение

Доступ: администратор либо директор с полным доступом. Нужны `import_prices` и `view_costs`, потому что исходный файл может содержать закупку даже в неиспользуемой колонке. Продавцам-консультантам импорт и исходные файлы недоступны.

Транспорт получает файл только с официального сервера Telegram, без переходов на другие адреса; размер ограничен и при скачивании потоком. Токены и пути скачивания не выводятся в журналы.

В закрытых таблицах хранятся разобранная таблица, имя и SHA256 исходного файла, настройки, снимки до/после и результат. Сам исходный бинарный CSV отдельно не архивируется. Данные импорта входят в резервную копию БД; автоматическое удаление истории пока не включено.

## Техническая проверка и выпуск

Миграция `0015_catalog_import.sql` добавляет единый RPC `bot_catalog_import`. Предпросмотр, применение и откат проверяют текущие права и владельца операции. Короткая транзакционная блокировка каталога/закупок защищает от параллельных вставок с тем же SKU; чтение витрины продолжается. Изменения и обязательный аудит записываются атомарно. Прежние неподключённые записывающие RPC импорта 0008 закрыты; их история сохранена.

Проверки: `npm test`, `python3 ops/tests/catalog-import.py`, `ops/dev/verify-catalog-import.ts prepare/resume`. SQL-проверка выполняется в отдельном PostgreSQL без сети и проверяет 1105 товаров, конкуренцию, доступ, исключение/повторный импорт, откат, историю заказов и отказ аудита. Включена в GitHub verify.

Фактические SHA, backup и результаты DEV-доставки — в STATUS.md и VERIFICATION.md. До production нужны отдельное применение 0014/0015 в собственной рабочей базе, реальные прайсы и проверка их форматов. Автодеплой не выполняет миграции. Main разрешён только по отдельной команде владельца после release review.
