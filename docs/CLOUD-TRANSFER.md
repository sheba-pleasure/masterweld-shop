# Подготовка переноса в самостоятельный магазин

Дата: 06.11.2026. Статус: закрытая репетиция первоначальной загрузки прошла. Рабочего импорта не было; выпуск не разрешён.

## Решения владельца

Два заказа от 22 и 27 октября сохраняются. Владелец ответил: «Пока не знаю — оставить решение открытым». Они не объявлены учебными, выполненными или отменёнными. Пока они не становятся активными заказами новой системы и не порождают уведомлений. Исходные строки доступны только в закрытом архиве. Окончательный способ учёта остаётся открытым.

В исходной базе четыре сотрудника; наличие строки или старой роли не означает согласованные права в новом магазине. Владелец есть в источнике, но рабочие права автоматически не переносятся. Валентина и Светлана пока не подтвердили свои Telegram ID.

Каталог ещё требует разбора. Исходная публикация сохранена только в закрытой проверочной копии, чтобы доказать точность переноса. Она не означает решения продавать все прежние товары на новом сайте.

## Что подготовлено

Команда создаёт закрытые списки сверки:

| Файл | Назначение |
|---|---|
| products-review.csv | Исходные ID, slug, артикул, категория и статус; решение о продаже остаётся UNDECIDED |
| categories-map.csv | Категории и родительские связи без автоматической переклассификации |
| staff-review.csv | Старые сотрудники и роли; новые права не назначены |
| orders-review.csv | ID, дата, состав по числу позиций и сумма; решение открыто |
| photos-map.csv | Исходные URL и привязка к товару; bytes_verified=false, целевой URL пуст |
| report.json | Снимок, контрольные суммы, результаты и явное releaseReady=false |

Это материалы сверки, не формат загрузки команд. Изменение CSV не применяет решения к базе. Файлы содержат служебные данные; они не попадают в Git, сайт или публичный DEV. Каталог имеет права 0700, файлы — 0600. Строки, похожие на формулы электронных таблиц, экранированы; при просмотре артикулов выбирайте текстовый тип, чтобы программа сохранила ведущие нули.

В источнике 39 категорий, 1038 товаров, 1077 записей фотографий с 1015 уникальными URL, два заказа, четыре сотрудника и шесть старых Telegram-квитанций. У 76 товаров артикул отсутствует; 24 группы артикулов повторяются после удаления внешних пробелов и приведения к нижнему регистру. Товары сохраняют свои ID и slug, включая товары непосредственно в родительских категориях. Повторяющиеся артикулы не объединяются. Обычный CSV-импорт по артикулу не заменяет этот первоначальный перенос.

## Запуск закрытой проверки

Только подготовка списков:

```sh
python3 ops/standalone/prepare-cloud-transfer.py \
  ops/.state/production/cloud-export/20261106T085019Z
```

С дополнительной репетицией на уже сохранённой резервной копии пустой целевой базы:

```sh
python3 ops/standalone/prepare-cloud-transfer.py \
  ops/.state/production/cloud-export/20261106T085019Z \
  --rehearse-target-backup ops/.state/production/rehearsals/20261106T133336Z-f9c9ecb9/report.json
```

Параметра рабочей базы нет. Инструмент не соединяется с Cloud, DEV или production, не читает токены и не запускает приложение/ботов. Он проверяет исходные размеры, хеши, состав колонок и единый снимок данных/метаданных. Для целевой копии проверяет закрытые пути, хеши дампа и ролей, production-маркер и точный журнал 0000–0013.

Репетиция создаёт новый PostgreSQL из локального образа с сетью none и без опубликованных портов. Восстанавливает резервную копию, применяет только явные 0014–0021 и загружает каталог с исходными ID. Первоначальная загрузка требует пустых прикладных таблиц, кроме технических справочников. Повторная загрузка блокируется целиком, поэтому эта команда не может повторным импортом вернуть позднее исключённые товары. Последующие прайсы обрабатываются отдельным механизмом [CATALOG-IMPORT.md](CATALOG-IMPORT.md).

Все восемь исходных наборов дополнительно сохраняются в mw_transfer_review.source_payloads. Схема закрыта для anon, authenticated и service_role. В активные staff, shop_orders и журнал сотрудников исходные строки не загружаются. Старые Telegram-квитанции переносятся как защита от повторной обработки; все шесть повторов отвергаются. Исходные Cloud ACL и служебные роли не копируются.

Проверяются исходные поля каталога, приватность архива/заказов/закупочных цен, отсутствие активных старых заказов/сотрудников/уведомлений, сохранение решения review, публичное чтение 1029 прежде опубликованных товаров внутри изолированного кластера. Затем выполняются dump/restore, перезапуск и восстановление исходной пустой резервной копии. Последняя сверка доказывает возврат к прежнему содержимому копии; это не испытание отката работающего сайта.

## Что осталось до рабочего переноса

1. Сохранить байты существующих фотографий и таблицу URL/контрольных сумм. Наличие ссылок не означает сохранность файлов.
2. Историческая прикладная копия уже сохранена на Яндекс.Диск и восстановлена после скачивания. Дополнить её фотографиями и свежими данными, проверить восстановление на другом сервере; [BACKUP-YANDEX.md](BACKUP-YANDEX.md).
3. Определить ассортимент и исключения, подтвердить реальные права. Решение по двум старым заказам оставить открытым до ответа владельца.
4. Подготовить отдельно проверяемую процедуру рабочего импорта с утверждёнными решениями. Текущий инструмент намеренно выполняет только закрытую репетицию.
5. Перед переключением получить свежий снимок и сверить изменения, согласовать момент остановки старого пути записи.
6. Проверить домен, рабочий выпуск/откат, оба бота и получателей уведомлений. Обновление main допустимо только после отдельного «обнови main» и свежего release review.

Настоящая production-база остаётся 0000–0013, DEV — 0000–0022. Приведённые здесь закрытые репетиции доходят до 0021; новая 0022 требует отдельного прогона. Эти проверки не обновляют приложение или main. Подробности исходного архива: [CLOUD-EXPORT.md](CLOUD-EXPORT.md); общий список блокеров: [PRODUCTION-PREFLIGHT.md](PRODUCTION-PREFLIGHT.md).
