# Следующие шаги

Актуально 06.11.2026. Фактическая готовность — в STATUS.md.

1. Завершить приёмку DEV владельцем: путь сайта до обработки заказа и уведомления проверены. Остальных сотрудников назначать явно; каждый должен запустить тестового бота. Привести время в карточках к явно указанному часовому поясу.
2. Импорт: файл → колонки/наценка → предпросмотр → подтверждение → применение → откат на учебном товаре.
3. Фото: частное хранение, проверки, предпросмотр, публикация и откат; загрузка файла пока не закончена.
4. Надёжность: очередь новых заказов в DEV готова; далее общий outbox ответов webhook/CRM и удобное управление неопределёнными доставками без повторной мутации.
5. Production: ревизия Cloud-БД, отдельные ключи/бот/instance_id, backup/restore, публичные production-параметры GitHub, испытание автодеплоя/отката. GitHub авторизован, ограниченный SSH уже настроен.
6. Перед покупателями: документы магазина, оплата/доставка/данные, законченные сценарии сотрудников.
7. Отдельно: кабинет, CRM, почта, AI, SEO. Кнопки, SQL и прототипы не означают готовность.

После «обнови main» заново оценить приоритеты по текущим фактам; старые утверждения о готовности не переносить без проверки.
